# AgentAura ESP32-C6 首页、桌宠动画与网页管理交接

更新时间：2026-07-17  
分支：`feat/v0.3.0-pet-bubble`  
基线提交：`ba52fa2`

## 1. 本轮目标

1. 首页显示缇犬 v2 桌宠，并播放动画。
2. 支持页面切换和远程切换桌宠状态。
3. 在设备 HTTP 地址提供中文管理页面。
4. 将原有 7 个逻辑状态扩展到 11 个状态。

## 4. 当前未解决问题

### 4.1 网页仍未完成运行验证

最后一次设备测试使用的是 04:25 启动的固件，而当前可编译产物生成于 04:29。需要先刷入最新固件，再分别测试：

```text
http://192.168.0.115/api/state
http://192.168.0.115/
```

如果 `/api/state` 也失败，问题在主循环或 HTTP 生命周期；如果 `/api/state` 正常而 `/` 失败，问题在管理页响应发送。

### 4.2 11 行动画未接入

曾尝试将所有帧转为 RGB565 RLE 并放入 LittleFS。该方案出现两个问题：

1. 当前 Arduino-ESP32/PlatformIO 组合编译 LittleFS 时无法稳定解析 `FS.h` 依赖。
2. 在 UI/LVGL 路径同步读取或分片解码后，设备出现 HTTP 不响应、动画不刷新等回归。

因此当前已禁用该路径，恢复为 `tiquan_v2_idle.h` 的内置 idle 动画。

### 4.3 `ui_manager.cpp` 需要整理

该文件原有大量乱码注释，部分注释和代码落在同一物理行，曾导致：

- `if` 被意外注释或额外解析；
- `ui_loop()` 花括号层级错误；
- 后续函数被编译器判断为定义在 `ui_loop()` 内部；
- 强制调用 `lv_refr_now()`，导致主循环疑似阻塞。

当前通过 `#if 0` 隔离了两段坏代码，固件可以生成，但建议下一步将 `ui_manager.cpp` 的相关函数重新整理为干净 UTF-8 代码，删除临时 `#if 0` 和未使用变量，而不是继续补括号。

## 5. 建议接手顺序

1. 刷入 04:29 之后生成的最新 `firmware.bin`，不要上传文件系统。
2. 保持串口监视器开启，验证设备是否持续运行 30 秒以上。
3. 先请求 `/api/state`，再请求 `/`，记录 HTTP 状态和串口输出。
4. 若 HTTP 仍失败，在 `comm_loop()`、`http_loop()` 和 `ui_loop()` 前后加入低频心跳日志，确认是哪一个调用不返回。
5. 重写 `ui_loop()` 和 `_switch_page_by_swipe()` 的损坏区域，消除乱码代码行及临时 `#if 0`。
6. 确认网页与 idle 动画稳定后，再设计 11 行动画加载方式。
7. 11 行动画建议优先评估：单独资源任务、双缓冲、每帧完成后通过 UI 消息提交；不要在 LVGL timer 回调中进行文件 I/O。

## 6. 构建与刷写

项目目录：

```text
Arduino_ESP32_AMOLED_Pet
```

构建：

```powershell
pio run -e esp32c6
```

上传前必须退出串口监视器，否则 COM4 会报 `PermissionError(13)`：

```powershell
pio run -e esp32c6 -t upload
```

当前基线不需要执行 `uploadfs`。

## 7. 验收标准

当前阶段最小验收：

1. 固件编译成功。

4. `/` 显示中文管理页面。
5. idle 动画持续播放，网页请求期间不停止。
6. 网页发出状态命令后，`/api/state` 返回对应的新状态。
