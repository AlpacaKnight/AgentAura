# AgentAura ESP32-C6 首页、桌宠动画与网页管理交接

更新时间：2026-07-20
分支：`feat/v0.3.0-pet-bubble`
基线提交：`403a7e0`

## 1. 本轮目标

1. 首页显示缇犬 v2 桌宠，并播放动画。
2. 支持页面切换和远程切换桌宠状态。
3. 在设备 HTTP 地址提供中文管理页面。
4. 将原有 7 个逻辑状态扩展到 11 个状态。

## 2. 当前结论

当前固件已在真实 ESP32-C6 AMOLED 设备上完成构建、刷写和接口验证：

- 中文管理网页和 `/api/state` 可正常访问。
- SPIFFS 中的 `sprites.rle` 可加载完整 11 行动画；内置 idle 仅作为资源加载失败时的回退图。
- 状态切换后 `animation_row` 会立即变化，`animation_frame` 会持续推进。
- `busy` / `processing` 已映射到 `review`（第 8 行），PetDesktop 使用相同映射。
- 网页修改亮度和音量会立即作用于硬件，并在 500ms 内同步设备设置页的滑块和数字。
- 动画资源启动加载保留 24KB 安全堆空间，并以 3 秒间隔最多重试 10 次，以兼容刷机后首次自动启动时的瞬时内存波动。

## 4. 当前注意事项

### 4.1 首次部署必须上传 SPIFFS

普通固件烧录不会更新宠物资源分区。新设备、分区表变化或资源更新后，需要额外执行 `uploadfs`。如果 `/api/state` 返回 `pet.assets_ready=false`，设备会显示内置 idle 回退图，并在启动后的约 30 秒内重试加载。

### 4.2 资源加载的内存约束

RGB565 单帧缓冲约 79,872 字节。资源加载前会检查空闲堆和最大连续块，并保留 24KB 安全空间。刷机触发的首次自动重启可能存在 USB/无线初始化造成的瞬时堆波动，因此加载逻辑最多重试 10 次。

### 4.3 源文件编码

`ui_manager.cpp` 和 `platformio.ini` 仍有早期遗留的乱码注释。功能代码已经可以正常构建运行，但后续整理时应保持 UTF-8，并避免仅为清理注释而改动运行逻辑。

## 5. 建议接手顺序

1. 先通过 `/api/state` 检查 `pet.assets_ready`、`animation_row` 和 `animation_frame`。
2. 如果 `assets_ready=false`，确认已经上传 SPIFFS，并检查串口中的 `[pet]` 加载日志。
3. 分别发送 `agent busy`、`agent waiting`、`agent error`，确认动画行为 `8`、`6`、`5` 且帧号持续变化。
4. 在管理网页修改亮度和音量，确认硬件立即生效，设置页控件在 500ms 内同步。
5. 资源格式或图集变化时，重新运行 `tools/generate_tiquan_rle.py`，随后重新上传 SPIFFS。

## 6. 构建与刷写

项目目录：

```text
Arduino_ESP32_AMOLED_Pet
```

构建并上传固件：

```powershell
uv run pio run -e esp32c6
uv run pio run -e esp32c6 -t upload --upload-port COM4
```

首次部署或 `sprites.rle` 更新后上传 SPIFFS：

```powershell
uv run pio run -e esp32c6 -t uploadfs --upload-port COM4
```

上传前必须退出串口监视器，否则 COM4 会报 `PermissionError(13)`。

3. `/` 显示中文管理页面。
4. 11 个宠物状态均能切换到对应动画行，`animation_frame` 持续推进。
5. `busy` 在硬件和 PetDesktop 中均显示 `review` 动画。
6. 网页修改亮度和音量后，真实硬件与设备设置页控件同步。
7. 网页请求、触摸滑动和动画播放可以同时工作。
